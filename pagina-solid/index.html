FUNDAMENTOS

Los cinco principios SOLID

Selecciona una tarjeta para conocer su significado.

S

Single Responsibility

Responsabilidad única

Una clase debe tener una sola razón para cambiar.

Separa las responsabilidades para que los cambios en una función no afecten otras partes del sistema.

class Factura:
    def calcular_total(self):
        return 100
O

Open/Closed

Abierto/cerrado

Permite extender el software sin modificar innecesariamente el código existente.

Por ejemplo, puedes agregar un nuevo método de pago mediante una implementación adicional.

class Pago:
    def procesar(self, cantidad):
        raise NotImplementedError
L

Liskov Substitution

Sustitución de Liskov

Las implementaciones derivadas deben respetar el comportamiento esperado de su tipo base.

Una implementación debe poder sustituir a otra compatible sin romper las expectativas del programa.

I

Interface Segregation

Segregación de interfaces

Es preferible utilizar interfaces pequeñas y específicas.

Una impresora sencilla no debería implementar una operación de escaneo que no puede realizar.

D

Dependency Inversion

Inversión de dependencias

Los módulos deben depender de abstracciones, no de implementaciones concretas.

Un procesador de pagos puede trabajar con una interfaz común en lugar de depender de una pasarela de pago específica.

APLICACIÓN PRÁCTICA

SOLID en un proyecto real

Imagina que desarrollas una tienda virtual.

Ejemplo: sistema de pagos

  • S: separar pedidos, facturas y notificaciones.
  • O: agregar métodos de pago sin reescribir el procesador.
  • L: respetar el contrato de cada método de pago.
  • I: dividir interfaces según las operaciones necesarias.
  • D: depender de una abstracción para procesar pagos.
